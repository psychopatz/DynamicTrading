Title: DynamicTradingCommon - Shared Library Architecture
Tags: [core, architecture, library, common, overview]

DynamicTradingCommon is the foundational shared library for the Dynamic Trading mod ecosystem. It provides core systems, APIs, and infrastructure that DynamicTradingV1 and V2 extend.

## Purpose

Provides reusable trading, economy, faction, and NPC systems that enable persistent dynamic economies in Project Zomboid multiplayer.

## Core Systems (10 Major Subsystems)

1. **Economy & Pricing System** - Multi-factor pricing with scarcity, events, faction modifiers
   - @DT_Economy_Common.lua - Core pricing mathematics
   - @DynamicTrading_Economy.lua - V2 economy wrapper
   - Dynamic stock generation, weighted item selection

2. **Stock Management** - Per-trader inventories with restock cycles
   - @DynamicTrading_Stock.lua
   - 24-hour restock cycles, scarcity pricing (0 qty = 1.5x, <5 qty = 1.2x)

3. **Faction System** - Persistent faction groups with daily simulation
   - @DynamicTrading_Factions.lua - Main API facade
   - @Lifecycle.lua - Faction creation and initialization
   - @Simulation.lua - Daily production/consumption/casualties
   - Tracks wealth, stockpiles, reputation, member count per faction

4. **NPC/Roster System** - Persistent NPC identities and trader registry
   - @DT_NPC_Archetypes.lua - Custom NPC definitions
   - @DT_NPC_Wardrobe.lua - Outfit presets by archetype/gender
   - @DynamicTrading_Roster.lua - Soul registry and trader tracking

5. **Quest System** - Dynamic quest package items with weight scaling
   - @DT_QuestManager.lua - Quest item creation/validation
   - 7 package types (Small/Medium/Large/Fragile/Medical/Military/Gift)

6. **Event System** - 30+ dynamic world events affecting economy
   - @DT_EventManager.lua - Event registration and processing
   - Flash/Meta/Seasonal event types with price modifiers, casualties, injections

7. **Network & Multiplayer** - Server authority with client synchronization
   - @DynamicTrading_Network_Server.lua - Main command dispatcher
   - @DataHandlers.lua - Data sync handlers
   - @TradeHandlers.lua - Transaction validation/execution
   - ModData-based persistence with selective transmit

8. **Dialogue System** - Contextual NPC responses with 27 language support
   - @DT_DialogueManager.lua - Dialogue rendering API
   - Archetype-specific variants (greetings, buying, selling, idle, quests)

9. **Configuration System** - Sandbox options, tags, archetypes, radio tiers
   - @Config.lua - Configuration API and data loading
   - @Tags.lua - Tag registry with price/weight modifiers
   - @sandbox-options.txt - Sandbox configuration options

10. **Location & Loot** - Town-based spawning and world loot integration
    - DT_FactionLocationManager.lua - Town location aggregation
    - DT_LootSystem.lua - World loot integration

## Key Entry Points

- **@00_DT_Core.lua** - Main initialization, creates global DynamicTrading table, registration APIs
- **@Config.lua** - Loads archetype definitions, dialogue, item master list
- System files auto-register on load (Factions, Economy, Events, etc.)

## Data Persistence (ModData Keys)

- `DynamicTrading_Factions` - Faction data (server authority)
- `DynamicTrading_Roster` - Trader/Soul registry (server authority)
- `DynamicTrading_Stock` - Trader inventories (server authority)
- `DynamicTrading_Engine_v2` - Global engine state (server authority)
- `DynamicTrading_Logs_*` - Network log history (synced to clients)

## Custom Events

- `OnDynamicTradingDailySimulation` - Daily faction/economy update tick
- `OnDynamicTradingHourlyTick` - Hourly simulation trigger
- `OnDynamicTradingTraderUpdated` - UI/Network sync notification
- `OnDynamicTradingFactionUpdated` - Faction state change
- `OnDynamicTradingStockUpdated` - Player inventory sync
- `OnDynamicTradingTradeCompleted` - Trade completion notification

## Integration with V1/V2

**DynamicTradingCommon Provides:**
- Configuration & registration APIs (RegisterArchetype, AddItem, RegisterTag)
- Shared economy math and pricing algorithms
- Faction lifecycle and daily simulation
- Event system and registry
- Network layer and command handlers
- Item master list and tag system
- Core UI templates and dialogue

**V1/V2 Provide:**
- Version-specific NPC generation systems
- Custom dialogue variants and interactions
- UI customization and styling
- Trader spawning mechanics
- Quest system refinements

## Registration APIs

```lua
-- Register custom archetype
DynamicTrading.RegisterArchetype("MyType", {
    allocations = { { tags={"Food"}, count=5 } },
    expertTags = { "Food" },
    wants = { "Resource.Fuel" = 1.5 },
    forbid = { "Weapon" }
})

-- Add item to master list
DynamicTrading.AddItem("Base.MyItem", {
    basePrice = 50,
    tags = { "Custom.Category" },
    stockRange = { min=1, max=10 }
})

-- Register tag with modifiers
DynamicTrading.RegisterTag("MyTag", {
    priceMult = 1.5,
    weight = 50
})

-- Register event
DynamicTrading.Events.Register("MyEvent", {
    name = "My Event",
    type = "flash",
    sentiment = "Positive",
    priceModifier = { "Food" = 0.5 }
})
```

## Sandbox Options

- `PriceBuyMult` (0.1-10.0, default 1.0) - Global buy price multiplier
- `PriceSellMult` (0.0-5.0, default 0.5) - Global sell price multiplier
- `StockMult` (0.1-5.0, default 1.0) - Inventory quantity multiplier
- `MaxLogs` (5-50, default 12) - Network log retention
- `GlobalWealthStart` (0-10M) - Initial faction wealth
- Wallet settings (min/max cash, empty/jackpot chance)

## Performance Optimizations

- Lazy loading of soul brain data (on-demand)
- Roster filtering (only "Trading" status synced over network)
- Selective ModData transmit (not global broadcast)
- Batch item loading to reduce initialization spam
- Weighted pools for O(n) random selection
- Network log pruning (configurable max entries)

## Key Dependencies

- Project Zomboid Build 42+ (uses Build 42 item system)
- No external mod dependencies (standalone library)
- Compatible with both singleplayer and multiplayer
