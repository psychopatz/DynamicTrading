Title: Event Creation Guide & Definition Schema
Tags: [chunk, internal, events, creation, schema]

EVENT REGISTRATION SYNTAX:

Basic registration:
```
DynamicTrading.EventManager.RegisterEvent("supply_shortage", {
  name = "Supply Shortage",
  category = "flash",
  type = "negative",
  priceMult = 1.4,
  stockMult = 0.4,
  affectedTags = {"Food", "Medical"},
  duration = 24,  -- hours
  description = "Market shortage drives prices up and stock down"
})
```

CATEGORY OPTIONS:

Flash Events (transient, 4-48 hours):
  - Supply shortage, panic buying, weather impact
  - Quick in/out, single-day mechanics
  - High probability (20-40% trigger chance per day)

Meta Events (state-altering, 2-7 days):
  - Regional famine, economic collapse, recovery
  - Longer duration, compound effects
  - Medium probability (10-20%)

Seasonal Events (cyclical, tied to season):
  - Winter prep, harvest abundance, spring growth
  - Predictable timing (same day each season)
  - Enabled by sandbox toggle

TYPE OPTIONS:

Negative (price spike, stock shortage):
  exampleEvent = {type="negative", priceMult=1.6, stockMult=0.3}
  Effect: Items become expensive + rare
  Use case: War, disaster, supply chain collapse

Positive (price drop, stock glut):
  exampleEvent = {type="positive", priceMult=0.65, stockMult=1.4}
  Effect: Items cheap + abundant
  Use case: Market flooding, seasonal abundance

Neutral (redistribute only):
  exampleEvent = {type="neutral", priceMult=1.0, stockMult=1.0, tags={"Alcohol"}}
  Effect: Category-specific behavior without price change
  Use case: Taxation, regulatory events

AFFECTED TAGS:

Single category:
  affectedTags = {"Food"}  -- ALL food items affected

Multiple categories:
  affectedTags = {"Food", "Medical", "Resource"}

Specific subtag:
  affectedTags = {"Food.Cooking", "Medical.Surgical"}

Wildcard expansion:
  -- Food.Cooking & Food.Perishable & Food.Drink all included
  affectedTags = {"Food.*"}

INTENSITY MODIFIER (optional):

Modifier range: 0.5 to 2.0
Effect on multipliers:
  intensity = 0.5 → priceMult 1.4 becomes 1.2, reduce effect by half
  intensity = 1.0 → normal effect (default)
  intensity = 1.5 → priceMult 1.4 becomes 1.6, amplify by 50%

Usage:
```
DynamicTrading.EventManager.TriggerEvent("supply_shortage", duration, intensity)
  -- duration overrides registered duration
  -- intensity scales multipliers proportionally
```

COMPOUND EFFECT CALCULATION:

Multiple events active:
  Event 1: priceMult = 1.4 (shortage)
  Event 2: priceMult = 0.8 (discount)
  Affected items compound: 1.4 * 0.8 = 1.12x final price

Combining with economics:
  Base price: 50
  Event 1: 50 * 1.4 = 70
  Event 2: 70 * 0.8 = 56
  Final: 56 (middle ground)

PERSISTENCE & TRIGGERING:

Manual trigger (admin/quest):
```
DynamicTrading.EventManager.TriggerEvent("supply_shortage", 48)
-- Starts event for 48 hours
```

Automatic triggers (hourly check):
- Probability: eventChance (sandbox setting)
- Frequency: eventFrequency (e.g., every 2 days)
- Random selection from registered events
- Duration randomized ±10% from registered value

Halting events (admin command):
```
DynamicTrading.EventManager.HaltEvent("supply_shortage")
-- Deactivate immediately, restore normal prices
```

FACTION-SPECIFIC EVENTS (advanced):

Limit event to specific faction:
```
DynamicTrading.EventManager.TriggerEvent("supply_shortage", 48, 1.0, "merchant_guild")
-- Only affects merchant_guild NPC prices/stock
```

Faction reputation tie-in:
- High reputation → frequency of negative events reduced
- Low reputation → frequency of negative events increased
- Implementation: EventManager checks faction.reputation before trigger

SEASONAL EVENTS:

Registration (once at init):
```
DynamicTrading.EventManager.RegisterSeasonalEvent("summer_harvest", {
  season = "summer",
  day = 1,  -- 1st of summer
  affectedTags = {"Food"},
  priceMult = 0.6,
  stockMult = 1.5
})
```

Activation (automatic):
- Winter: day 1 → triggers winter_prep (if enabled)
- Spring: day 1 → triggers spring_growth
- Summer: day 1 → triggers summer_harvest
- Fall: day 1 → triggers autumn_stockpile
