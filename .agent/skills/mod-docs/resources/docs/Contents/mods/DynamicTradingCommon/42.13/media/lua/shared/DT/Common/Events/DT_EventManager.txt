Title: DT_EventManager - Dynamic Event System with Registration and Processing
Tags: [events, manager, registration, flash, seasonal, meta, processing, factions]

Unified event system managing 30+ dynamic world events. Handles registration, hourly processing, cooldowns, faction integration, and price/stock modifications. Supports Flash, Seasonal, and Meta event types.

## Purpose

Creates dynamic economy fluctuations through world events that affect prices, stock availability, faction casualties, and resource consumption. Events activate based on conditions, random lottery, or time-based triggers.

## Event Types

### Flash Events (Random Lottery)
- **Duration:** 3-7 days (sandbox configurable)
- **Activation:** Random chance based on frequency/interval
- **Examples:** Gold Rush, Plague, War, Tech Boom, Smugglers
- **Cooldown:** 14 days after expiration
- **Max Concurrent:** 3 (sandbox configurable)

### Seasonal Events (Condition-Based)
- **Duration:** Persistent while condition true (-1 = infinite)
- **Activation:** Auto-activates when `condition()` returns true
- **Examples:** Winter (game month), Summer, Harvest
- **Cooldown:** None (reactivates on next condition match)

### Meta Events (World Conditions)
- **Duration:** Persistent while condition true
- **Activation:** Always-on if condition met
- **Examples:** Long-term world state changes
- **Cooldown:** None

## Event Definition Structure

```lua
{
    id = "eventID",                           -- Unique identifier
    name = "Display Name",                    -- Human-readable name
    type = "flash"|"meta"|"seasonal",         -- Event type
    sentiment = "Positive"|"Negative",        -- For UI/logging
    duration = 5,                             -- Days (flash only, ignored for meta/seasonal)
    priceModifier = { [tag] = multiplier },   -- Tag-based price changes
    itemInjections = { [tag] = count },       -- Force items into stock
    volumeModifier = { [tag] = multiplier },  -- Stock quantity changes
    forbidTags = { [tag] = true },            -- Tags to exclude from stock
    targetCasualties = number,                -- Faction deaths (distributed over duration)
    attrition = {                             -- Resource-dependent deaths
        resource = "meds"|"food"|"fuel",      -- Resource type needed
        pct = 0.4,                            -- % of faction affected
        cost = 1.5                            -- Resource per affected person
    },
    consumptionModifier = {                   -- Increase daily consumption
        food = 1.5,                           -- 50% more food burn
        meds = 2.0                            -- 100% more meds burn
    },
    demographics = {                          -- Global population effects
        attritionAdd = 0.02                   -- +2% daily passive deaths
    },
    condition = function()                    -- Activation condition (seasonal/meta only)
        return getGameTime():getMonth()== 11  -- Example: Winter (December)
    end
}
```

## Registration API

### DynamicTrading.Events.Register(id, data)

Registers event in global registry.

**Parameters:**
- `id` (string) - Unique event ID
- `data` (table) - Event definition (see structure above)

**Usage:**
```lua
DynamicTrading.Events.Register("GoldRush", {
    name = "Gold Rush",
    type = "flash",
    sentiment = "Positive",
    duration = 5,
    priceModifier = {
        ["Currency"] = 0.5,           -- Currency 50% cheaper
        ["Misc.Cosmetic"] = 2.0       -- Luxury items 2x expensive
    },
    itemInjections = {
        ["Quality.Luxury"] = 5        -- Force 5 luxury items
    }
})
```

**Behavior:**
- Stores in `DynamicTrading.Events.Registry[id]`
- Prints confirmation with type and sentiment
- Type defaults to "flash" if not specified

## Event Processing

### DynamicTrading.Events.Tick(data)

Hourly event system update. Handles expiration, meta/seasonal conditions, and flash event lottery.

**Called by:** `OnDynamicTradingHourlyTick` event

**Process:**

#### **Phase A: Cleanup & Cooldowns**

1. Check all active events for expiration
2. If `currentDay >= event.expires`:
   - Remove from activeEvents
   - Set 14-day cooldown: `SetEventCooldown(id, currentDay + 14)`
   - Log expiration
3. Transmit changes to clients

**Cooldown System:**
- Prevents same event from immediately retriggering
- Flash events only (meta/seasonal ignore cooldowns)
- Stored in `DynamicTrading.CooldownManager`

#### **Phase B: Meta & Seasonal Events**

1. For each meta/seasonal event in registry:
   - Evaluate `event.condition()` function
   - If condition true AND not active → Activate
   - If condition false AND active → Deactivate
2. Set `expires = -1` (infinite while condition true)
3. Log activation/deactivation
4. Auto-removes when condition no longer met

**Example:**
```lua
-- Winter event
condition = function()
    local month = getGameTime():getMonth()
    return month == 11 or month == 0 or month == 1  -- Dec, Jan, Feb
end

-- Auto-activates in December, stays active through Feb, auto-deactivates in March
```

#### **Phase C: Flash Event Lottery**

**Trigger Conditions:**
1. Active flash count < `MaxEvents` (default 3)
2. Days since last event >= `EventFrequency` (default 5)
3. Random roll <= `EventChance` (default 50%)

**Selection Process:**

1. **Build Candidate Pool:** All flash events in registry
2. **Filter by Status:**
   - **validPool:** Not active, cooldown expired
   - **cooldownPool:** Not active, still on cooldown (backup)
3. **Selection Priority:**
   - First try validPool (fresh events)
   - If empty, fallback to cooldownPool
4. **Activation:**
   - Random pick from selected pool
   - Set duration: `expires = currentDay + EventDuration`
   - Update `lastEventDay = currentDay`
   - Log and transmit

**Sandbox Configuration:**
```lua
SandboxVars.DynamicTrading = {
    MaxEvents = 3,         -- Max concurrent flash events (1-5)
    EventFrequency = 5,    -- Days between lottery checks (1-30)
    EventChance = 50,      -- % chance to trigger (0-100)
    EventDuration = 3      -- How long events last (1-14 days)
}
```

**Example Lottery:**
```
Day 10: lastEventDay = 5, daysSince = 5, frequency = 5 ✓
        Roll 45 <= 50 ✓
        Active flash count = 2 < 3 ✓
        Trigger lottery → Select random event → "Plague" activates
```

### DynamicTrading.Events.RebuildActiveCache(data)

Rebuilds `DynamicTrading.Events.ActiveEvents` array from ModData.

**Purpose:**
- Provides fast access to active event definitions
- Used by pricing/stock/UI systems
- Synced with ModData activeEvents table

**Process:**
1. Clear ActiveEvents array
2. For each active event ID in ModData:
   - Lookup definition in Registry
   - Add to ActiveEvents array
3. Count stored for debug logging

### DynamicTrading.Events.UpdateFaction(faction)

Processes event impacts on specific faction. Called during daily simulation.

**Called by:** Simulation.UpdateDaily() for each faction

**Process:**

#### **Step 1: Expiry Check**

If faction has ActiveFlashEvent and `currentHour >= expires`:
- Clear event from faction
- Reset targetCasualties to 0
- Return (allow new event trigger)

#### **Step 2: Stability Tracking**

```lua
if faction.state == "Stable":
    faction.consecutiveStableDays += 1
else:
    faction.consecutiveStableDays = 0
```

**Purpose:** Stable factions get bonus event chance (+10% per 7 days stable)

#### **Step 3: Trigger Roll**

```lua
baseChance = EventChance  -- Default 50%
stabilityBonus = floor(consecutiveStableDays / 7) × 10
roll = Random(1-100)

if roll > (baseChance + stabilityBonus):
    return  -- No event today
```

**Example:**
```
Faction stable for 21 days
Bonus: 21 / 7 = 3 weeks × 10% = +30%
Chance: 50% + 30% = 80%
Roll 75 <= 80 → Event triggers!
```

#### **Step 4: Candidate Discovery**

Build candidate pool based on faction state and tags:

1. **State-Based Events:**
   - If starving → Add negative events (Plague, Raid)
   - If stable → Add positive events (Celebration, Boom)

2. **Wildcard Pool:**
   - All other flash events
   - Selected if no state-based match

3. **Selection:**
   - Random pick from appropriate pool
   - Assign to `faction.ActiveFlashEvent`

#### **Step 5: Event Application**

From event definition, apply:

**A. Casualties (Distributed):**
```lua
targetCasualties = event.targetCasualties or 0
expires = currentHour + (duration × 24)

faction.ActiveFlashEvent = {
    id = eventID,
    expires = expires,
    targetCasualties = targetCasualties
}
```

Casualties applied daily in Simulation.UpdateDaily() (see @Lifecycle-and-Simulation.txt)

**B. Attrition (Resource-Dependent):**
Applied daily in simulation (embedded in event def)

**C. Consumption Modifiers:**
Global engine modifiers applied during daily burn calculation

## Event Effect Types

### Price Modifiers

Affects buy/sell prices for items with matching tags:

```lua
priceModifier = {
    ["Food"] = 1.5,      -- All food 50% more expensive
    ["Medical"] = 2.0,   -- Medical doubles in price
    ["Ammo"] = 0.5       -- Ammo 50% cheaper
}
```

**Application:** See @DT_Economy_Common.lua GetPriceModifier()

**Stacking:** Multiple active events multiply together

**Example:**
```
Event 1: Food ×1.5
Event 2: Food ×1.2
Final: Food ×1.8 (1.5 × 1.2)
```

---

### Item Injections

Forces specific tagged items into trader stock:

```lua
itemInjections = {
    ["Winter"] = 3,           -- Add 3 winter items
    ["Illegal"] = 2,          -- Add 2 contraband items
    ["Quality.Luxury"] = 5    -- Add 5 luxury items
}
```

**Application:** GenerateStock() allocations phase (see @DT_Economy_Common.lua)

**Behavior:**
- Guarantees items appear even if archetype forbids them
- Bypasses normal weighted selection for these slots
- Uses tag matching (finds all items with matching tags)

---

### Volume Modifiers

Changes stock quantities for tagged items:

```lua
volumeModifier = {
    ["Food"] = 0.5,     -- 50% less food in stock
    ["Ammo"] = 2.0      -- 200% more ammo
}
```

**Application:** GenerateStock() quantity calculation

**Formula:**
```
qty = baseQty × diffMult × volumeMult × globalMult
```

---

### Forbidden Tags

Prevents tagged items from spawning:

```lua
forbidTags = {
    ["Food.Fresh"] = true,    -- No fresh food
    ["Medical"] = true        -- No medical supplies
}
```

**Application:** GenerateStock() item filtering

**Use Case:** Scarcity events (Drought removes crops, Blockade removes imports)

---

### Casualties (Faction Deaths)

Distributed deaths over event duration:

```lua
targetCasualties = 20  -- 20 total deaths over event

Day 1: Kill 5 (20/4 remaining days)
Day 2: Kill 5 (15/3)
Day 3: Kill 5 (10/2)
Day 4: Kill 5 (5/1)
```

**Variance:** 30% chance to reduce daily casualties by 1

**Application:** Simulation.UpdateDaily() (see @Lifecycle-and-Simulation.txt)

---

### Attrition (Resource Deaths)

Resource-dependent conditional deaths:

```lua
attrition = {
    resource = "meds",
    pct = 0.4,      -- 40% of faction affected
    cost = 1.5      -- 1.5 meds per person
}
```

**Process:**
1. `affectedCount = floor(memberCount × 0.4)`
2. `totalNeeded = affectedCount × 1.5`
3. If `stockpile.meds >= totalNeeded`: Pay cost, no deaths
4. Else: **20% of affected die**

**Example:**
```
50 members, 40% affected = 20 people
Need: 20 × 1.5 = 30 meds
Stockpile: 15 meds (insufficient)
Deaths: 20 × 0.2 = 4 casualties
```

---

### Consumption Modifiers

Increases daily resource burn rate:

```lua
consumptionModifier = {
    food = 1.5,    -- 50% more food consumed daily
    meds = 2.0     -- 100% more meds consumed daily
}
```

**Application:** Simulation.UpdateDaily() consumption phase

**Formula:**
```
burn = memberCount × baseConsumption × consumptionMult × eventMult
```

---

### Demographics (Global Attrition)

Passive population decline affecting all factions:

```lua
demographics = {
    attritionAdd = 0.02    -- +2% daily passive deaths
}
```

**Application:** Every faction loses `floor(memberCount × 0.02)` daily

**Use Case:** Long-term apocalypse pressure, radiation, disease spread

## Event Examples

### Positive Flash Event
```lua
DynamicTrading.Events.Register("TechBoom", {
    name = "Tech Boom",
    type = "flash",
    sentiment = "Positive",
    duration = 5,
    priceModifier = {
        ["Electronics"] = 0.7,      -- Electronics 30% cheaper
        ["Literature.Tech"] = 0.5   -- Tech books 50% cheaper
    },
    itemInjections = {
        ["Electronics"] = 10        -- Flood market with electronics
    },
    volumeModifier = {
        ["Electronics"] = 2.0       -- Double stock quantity
    }
})
```

### Negative Flash Event
```lua
DynamicTrading.Events.Register("Plague", {
    name = "Plague Outbreak",
    type = "flash",
    sentiment = "Negative",
    duration = 7,
    priceModifier = {
        ["Medical"] = 3.0          -- Medical 3x expensive
    },
    volumeModifier = {
        ["Medical"] = 0.3          -- 70% less medical stock
    },
    targetCasualties = 15,         -- 15 deaths over 7 days
    attrition = {
        resource = "meds",
        pct = 0.6,                 -- 60% infected
        cost = 2.0                 -- 2 meds per person to survive
    },
    consumptionModifier = {
        meds = 3.0                 -- 3x meds consumption
    }
})
```

### Seasonal Event
```lua
DynamicTrading.Events.Register("Winter", {
    name = "Harsh Winter",
    type = "seasonal",
    sentiment = "Negative",
    condition = function()
        local month = getGameTime():getMonth()
        return (month == 11 or month == 0 or month == 1)  -- Dec-Feb
    end,
    priceModifier = {
        ["Clothing.Winter"] = 2.0,  -- Winter gear 2x expensive
        ["Resource.Fuel"] = 2.5     -- Fuel 2.5x expensive
    },
    itemInjections = {
        ["Winter"] = 5              -- Add winter items
    },
    consumptionModifier = {
        food = 1.5,                 -- 50% more food (cold)
        fuel = 2.0                  -- Double fuel usage (heating)
    }
})
```

### Meta Event
```lua
DynamicTrading.Events.Register("Collapse", {
    name = "Societal Collapse",
    type = "meta",
    sentiment = "Negative",
    condition = function()
        local days = getGameTime():getDaysSurvived()
        return days > 180  -- After 6 months
    end,
    demographics = {
        attritionAdd = 0.01        -- +1% daily deaths globally
    },
    priceModifier = {
        ["Weapon"] = 2.0,
        ["Food"] = 1.8,
        ["Medical"] = 2.5
    }
})
```

## Performance Considerations

- **Hourly tick lightweight** - Only checks conditions and cooldowns
- **Flash lottery throttled** - Only checks every N days
- **Active cache** - Pre-built array for fast iteration
- **Cooldowns prevent spam** - 14-day minimum between repeats
- **Condition functions cached** - Evaluated once per hour

## Best Practices

1. **Set realistic durations** - 3-7 days for flash events
2. **Balance price modifiers** - 0.5-3.0 range typical
3. **Test casualty rates** - High casualties can wipe factions quickly
4. **Provide faction-level events** - Don't rely only on global
5. **Use attrition for diseases** - More realistic than instant deaths
6. **Combine effect types** - Price + volume + casualties creates depth
7. **Test condition functions** - Ensure proper activation/deactivation
