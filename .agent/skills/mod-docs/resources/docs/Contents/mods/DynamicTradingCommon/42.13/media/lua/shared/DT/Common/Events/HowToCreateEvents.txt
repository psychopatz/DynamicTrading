Title: How to Create & Register New Events
Tags: [guide, events, creation, tutorial, economy-system]

QUICK START (5-minute guide):

Step 1: Define Event Properties
```lua
local myEvent = {
  name = "Winter Shortage",
  category = "seasonal",
  type = "negative",
  priceMult = 1.4,
  stockMult = 0.4,
  affectedTags = {"Food"},
  duration = 48,
  description = "Cold weather makes food scarce"
}
```

Step 2: Choose Category Type
- flash: Quick, transient (4-48 hours)
- meta: State-altering (2-7 days)
- seasonal: Cyclical, tied to game seasons

Step 3: Choose Event Type
- negative: Price spike + stock shortage
- positive: Price drop + stock glut
- neutral: Category-specific mechanics only

Step 4: Select Affected Tags
- Single: {"Food"} (all food items)
- Multiple: {"Food", "Medical"} (food AND medical)
- Specific: {"Food.Cooking"} (exact subcategory)
- Wildcard: {"Food.*"} (all food subtypes)

Step 5: Set Duration
- Flash events: 12-48 hours
- Meta events: 48-168 hours (2-7 days)
- Seasonal: tied to game season

Step 6: Register Event
```lua
DynamicTrading.EventManager.RegisterEvent("winter_shortage", myEvent)
```

Step 7: Trigger Event (Admin/Quest)
```lua
DynamicTrading.EventManager.TriggerEvent("winter_shortage", 72)
```

Step 8: Test
- /dtm events list (see all registered)
- /dtm events trigger winter_shortage 48 (activate)
- /dtm events halt winter_shortage (deactivate)
- Check NPC prices in trading window

DETAILED EVENT STRUCTURE:

Required Properties:
```lua
{
  name = "Display Name",                  -- shown in UI/logs
  category = "flash|meta|seasonal",       -- event type
  type = "negative|positive|neutral",     -- effect direction
  priceMult = 1.4,                        -- price multiplier
  stockMult = 0.4,                        -- stock multiplier
  affectedTags = {"Tag1", "Tag2"},        -- which items affected
  duration = 48,                          -- hours (for non-seasonal)
  description = "Event description",      -- flavor text
}
```

Optional Properties:
```lua
{
  eventID = "unique_event_id",            -- auto-generated if omitted
  intensity = 1.0,                        -- default intensity (0.5-2.0)
  regionRestrictions = {"Muldraugh"},     -- limit to counties
  factionTarget = "merchants",            -- affect specific faction
  eventChain = "next_event_id",           -- trigger followup event
  prerequisites = {"prerequisite_event"}, -- require other event first
  icon = "path/to/icon.png",              -- visual representation
}
```

CATEGORY BREAKDOWN:

Flash Events (Quick, impactful):

Characteristics:
- Duration: 4-48 hours
- Frequent: Every few days
- High impact: Strong multipliers
- Supply/demand fluctuation

Examples:
```lua
-- Supply shortage
{name="Supply Shortage", category="flash", type="negative",
 priceMult=1.5, stockMult=0.3, affectedTags={"Food"},
 duration=24, description="Market shortage drives prices up"}

-- Panic buying
{name="Panic Buying", category="flash", type="negative",
 priceMult=1.2, stockMult=0.4, affectedTags={"Medical", "Tool"},
 duration=12, description="Panic causes hoarding"}

-- Surplus glut
{name="Surplus Glut", category="flash", type="positive",
 priceMult=0.6, stockMult=1.5, affectedTags={"Food"},
 duration=36, description="Overproduction floods market"}

-- Weather impact
{name="Heavy Rain", category="flash", type="negative",
 priceMult=1.3, stockMult=0.5, affectedTags={"Electronics"},
 duration=18, description="Rain damages deliveries"}
```

Meta Events (State-altering):

Characteristics:
- Duration: 2-7 days
- Rare triggering: Less frequent
- Compound effects: Stacks with other events
- Persistent state changes

Examples:
```lua
-- Regional famine
{name="Regional Famine", category="meta", type="negative",
 priceMult=2.0, stockMult=0.2, affectedTags={"Food"},
 duration=120, description="Widespread food shortage"}

-- Economic collapse
{name="Economic Collapse", category="meta", type="negative",
 priceMult=1.0, stockMult=0.6, affectedTags={"*"},  -- all items!
 duration=168, description="Market instability spreads"}

-- Recovery period
{name="Economic Recovery", category="meta", type="positive",
 priceMult=0.8, stockMult=1.3, affectedTags={"*"},
 duration=144, description="Market stabilization"}

-- War economy
{name="War Economy", category="meta", type="negative",
 priceMult=1.4, stockMult=0.5, affectedTags={"Weapon", "Medical"},
 duration=120, description="Military resource demand spikes"}
```

Seasonal Events (Predictable, cyclical):

Characteristics:
- Fixed schedule: 1st of each season
- Always activate if enabled: No randomness
- Sandbox toggle: AllowSeasonalEvents
- Immersive: Tie to calendar

Examples:
```lua
-- Winter preparation
{name="Winter Prep", category="seasonal", type="negative",
 priceMult=1.3, stockMult=0.6, affectedTags={"Food", "Clothing"},
 description="People stockpile before winter"}

-- Harvest abundance
{name="Harvest", category="seasonal", type="positive",
 priceMult=0.5, stockMult=2.0, affectedTags={"Food"},
 description="Abundant harvest season"}

-- Spring growth
{name="Spring Growth", category="seasonal", type="positive",
 priceMult=0.7, stockMult=1.4, affectedTags={"Clothing", "Tool"},
 description="Fresh supplies arrive"}

-- Summer heat
{name="Summer Heat", category="seasonal", type="negative",
 priceMult=1.5, stockMult=0.4, affectedTags={"Beverage", "Electronics"},
 description="Heat damages goods, need for cooling"}
```

TYPE BREAKDOWNS:

Negative Events (price spike + stock shortage):

priceMult range: 1.2-2.5
  - 1.2x = mild price increase (10% worse)
  - 1.5x = moderate increase (40% worse)
  - 2.0x = severe (double price)
  - 2.5x = extreme crisis

stockMult range: 0.2-0.6
  - 0.6x = still available (40% reduction)
  - 0.4x = rare items (60% reduction)
  - 0.2x = crisis shortage (80% reduction)

Use case: Wars, disasters, supply chain collapse

Positive Events (price drop + stock glut):

priceMult range: 0.5-0.8
  - 0.8x = mild discount (20% cheaper)
  - 0.6x = significant discount (40% cheaper)
  - 0.5x = deep discount (50% cheaper)
  - <0.5x = fire sale (extremely cheap)

stockMult range: 1.2-2.0
  - 1.2x = slightly above normal
  - 1.5x = abundant supply
  - 2.0x = flooding the market

Use case: Market flooding, seasonal abundance, sales

Neutral Events (redistribute only):

priceMult: 1.0 (no price change)
stockMult: 1.0 (no stock change)

For neutral events, use other mechanics:
- Region restrictions: Affect specific counties
- Faction targeting: Benefits/hurts specific NPCs
- Dialogue triggers: Change NPC behavior

Example:
```lua
{name="Taxation", category="meta", type="neutral",
 priceMult=1.0, stockMult=1.0,
 affectedTags={"Luxury"},  -- luxury items themed only
 description="Government taxation impacts luxury trade",
 factionTarget="merchants",  -- merchants pay taxes
 reputationEffect=-10  -- reputation penalty
}
```

AFFECTED TAGS SYNTAX:

Single category:
```lua
affectedTags = {"Food"}  -- ALL food items
```
Scope: Base.Bread, Base.CakeMix, Base.Sugar, etc.

Multiple categories:
```lua
affectedTags = {"Food", "Medical"}
```
Scope: Food items + Medical items

Specific subcategory:
```lua
affectedTags = {"Food.Cooking"}
```
Scope: Only Food.Cooking tagged items (not Drink/Meat)

Wildcard expansion:
```lua
affectedTags = {"Food.*"}
```
Scope: All Food subtypes (Cooking, Drink, Meat, Perishable, NonPerishable)

Multiple with wildcard:
```lua
affectedTags = {"Food.*", "Medical.Surgical"}
```
Scope: All food + medical surgical items

INTENSITY MODIFIER (Advanced):

Default intensity: 1.0

Use intensity to scale multiplier effects:
```lua
-- Base event defined with intensity 1.0
{name="Supply Shortage", priceMult=1.4, stockMult=0.4, ...}

-- Trigger with different intensities:
TriggerEvent("supply_shortage", 48, 0.5)  -- mild (1.2x price, 0.7x stock)
TriggerEvent("supply_shortage", 48, 1.0)  -- normal (1.4x price, 0.4x stock)
TriggerEvent("supply_shortage", 48, 2.0)  -- severe (1.8x price, 0.2x stock)
```

Calculation:
```
Final Multiplier = BaseMultiplier^intensity
1.4^0.5 = 1.18
1.4^1.0 = 1.40
1.4^2.0 = 1.96
```

REGION & FACTION TARGETING:

Limit event to specific area:
```lua
{name="Local Shortage", ...,
 regionRestrictions = {"Muldraugh", "West Point"},
 description="Shortage affects specific regions"
}
```
Effect: Only affects NPC trading in these counties

Target specific faction:
```lua
{name="Merchant Strike", ...,
 factionTarget = "merchants",
 description="Merchant guild goes on strike",
 stockMult = 0.1  -- merchants have almost nothing
}
```
Effect: Only merchant-faction NPCs affected

EVENT CHAINING:

Trigger events in sequence:
```lua
-- Event 1: Supply shortage (2 days)
{name="Supply Shortage", duration=48, eventChain="economic_panic"}

-- When shortage ends, automatically trigger:
{name="Economic Panic", eventID="economic_panic", duration=72, ...}
```

Setup:
```lua
DynamicTrading.EventManager.RegisterEvent("supply_shortage", event1)
DynamicTrading.EventManager.RegisterEvent("economic_panic", event2)

-- Trigger first, second follows automatically
TriggerEvent("supply_shortage", 48)
```

PREREQUISITES & GATING:

Require other events to happen first:
```lua
{name="Famine Recovery", ...,
 prerequisites = {"regional_famine"},
 description="Recovery after proven famine"
}
```
Effect:
- Can only trigger if "regional_famine" has been active
- Locks event type progression
- Create story causal chains

AUTOMATION & SCHEDULING:

Automatic triggering (no admin action needed):

Sandbox settings control frequency:
- EventFrequency: How often to check (2 = every 2 days)
- EventChance: Random probability (80% chance to trigger)
- EventDuration: Use registered default

Registration makes event eligible:
```lua
DynamicTrading.EventManager.RegisterEvent("supply_shortage", {...})
-- Every frequency check, has chance% to trigger this
```

Disable from auto-triggering:
```lua
{name="Special Event", category="meta", autoTrigger=false, ...}
-- Only triggers via manual command: /dtm events trigger special_event
```

SANDBOX CONFIGURATION:

Players control event system via sandbox:
- EventFrequency: 1-7 (frequency in days)
- EventChance: 0-100 (probability percent)
- EventDuration: 6-240 (default hours)
- AllowSeasonalEvents: true/false
- AllowNegativeEvents: true/false
- AllowPositiveEvents: true/false
- MinEventIntensity: 0.5-1.5
- MaxEventIntensity: 1.0-2.0

Examples:
- Hardcore server: AllFrequent, AllowAll, Intensity 1.5-2.0
- Casual: Infrequent, Balance both, Intensity 0.8-1.2
- Survival: Frequent negative, rare positive, Intensity 1.2-2.0

TESTING YOUR EVENTS:

Admin commands:
```
/dtm events list                  -- show all registered events
/dtm events list negative          -- filter by type
/dtm events trigger winter_shortage 48  -- activate manually
/dtm events active                -- show currently active
/dtm events halt winter_shortage   -- deactivate immediately
/dtm events info winter_shortage   -- show event details
/dtm debug                         -- show active events + multipliers
```

In-game validation:
1. Check prices changed (high/low based on event)
2. Check item quantities fluctuate
3. Check NPC dialogue reflects event
4. Verify duration counting down
5. Confirm event deactivates when timer expires

OPTIMIZATION TIPS:

Performance considerations:
- Limit affectedTags to necessary items (use specific tags)
- Avoid compound negative events (max 3 active simultaneously)
- Cache multiplier calculations (done automatically)
- Verify tag expansion (avoid expensive wildcard scans)

Event balancing:
- Test with multiple events active together
- Check compound effects (1.4 * 1.3 = 1.82x)
- Balance negative/positive frequency (prevent inflation)
- Verify faction-specific events don't break reputation system
