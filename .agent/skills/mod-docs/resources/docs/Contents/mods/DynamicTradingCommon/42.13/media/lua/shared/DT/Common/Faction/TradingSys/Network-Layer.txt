Title: DynamicTrading Network Layer - Multiplayer Command System
Tags: [network, multiplayer, server, client, commands, trade, sync, validation]

Server-authoritative multiplayer networking system. Handles trade transactions, data synchronization, and admin commands. Routes client requests through validation and executes atomic operations.

## Purpose

Provides secure, validated client-server communication for trading system. Ensures server authority on all critical data (wealth, stock, factions). Synchronizes state changes to clients.

## Architecture

**Entry Point:** @DynamicTrading_Network_Server.lua
- Loads three handler modules: DataHandlers, TradeHandlers, DebugHandlers
- Listens on `Events.OnClientCommand` for two modules:
  - `"DynamicTrading_V2"` - Primary V2 commands
  - `"DynamicTrading"` - Shared/legacy commands

**Handler Structure:**
```lua
Handlers = {
    CommandName = function(player, args)
        -- Validation
        -- Execution
        -- Response via SendResponse()
    end
}
```

**Response Pattern:**
All use `ServerHelpers.SendResponse(player, MODULE, COMMAND, data)`:
- Packaged as table with metadata
- Sent via `sendServerCommand()`
- Client listens on `Events.OnServerCommand`

## Data Sync Commands

**Handler:** @networkServer/DataHandlers.lua

### RequestTrader → SyncTrader
Fetches trader visual and location data.

**Client Sends:**
```lua
sendClientCommand("DynamicTrading_V2", "RequestTrader", { traderID = uuid })
```

**Server Responds:**
```lua
{
    traderID = uuid,
    visuals = { model, outfit, hairStyle, etc },
    factionID = factionID,
    homeCoords = { x, y, z, town, name },
    isPhysicallySpawned = boolean
}
```

**Use Cases:**
- UI display (portrait, name)
- Map markers
- Trader spawning

---

### RequestRoster → SyncRoster
Fetches minimal soul list and global events.

**Client Sends:**
```lua
sendClientCommand("DynamicTrading_V2", "RequestRoster", {})
```

**Server Responds:**
```lua
{
    souls = {
        [uuid] = {
            name, archetypeID, factionID, status,
            homeCoords, portraitID
        }
    },  -- ONLY "Trading" status souls
    factionMembers = {
        [factionID] = memberCount
    },
    activeGlobalEvents = { eventDef1, eventDef2 }
}
```

**Filtering:**
- Only includes souls with `status == "Trading"`
- Reduces bandwidth (excludes Dead/Roaming)

**Use Cases:**
- Trader radar/map
- Population display
- UI event notifications

Forces trader stock regeneration (admin).

## Trade Commands

**Handler:** @NetworkServer/TradeHandlers.lua

### TradeTransaction (BUY)

Player purchases from trader.

**Client Sends:**
```lua
sendClientCommand("DynamicTrading_V2", "TradeTransaction", {
    traderUUID = uuid,
    item = "Base.Apple",
    quantity = 5,
    transactionType = "buy"
})
```

**Server Process:**

1. **Validation:**
   - Item exists in MasterList
   - Trader has stock (qty >= requested)
   - Calculate price via `Economy.V2.GetBuyPrice()` (includes condition)
   - Player wealth >= total cost

2. **Execution (Atomic):**
   ```lua
   RemoveMoney(player, totalCost)
   DecreaseStockQty(traderID, itemKey, qty)
   IncreaseFactionWealth(factionID, totalCost)
   AddItemWithCondition(player, itemKey, qty, customData)
   ```

3. **Heat Update:**
   ```lua
   For each item tag:
       globalHeat[tag] += (sensitivity × qty)
   ```
   **Sensitivity:** Sandbox configurable (default 0.001)
   **Purpose:** Creates inflation as items are bought

4. **Sync Response:**
   ```lua
   TradeResult = {
       success = true,
       itemName = displayName,
       price = totalCost,
       basePrice = itemBasePrice,
       isBuy = true
   }
   SyncStock = { updated trader inventory + faction wealth }
   ```

**Custom Condition Handling:**
```lua
AddItemWithCondition(player, itemKey, qty, customData)
  → For each qty:
      Create item → Apply customData:
        - If fluidAmount: setFluidAmount(amt)
        - If usedDelta: setUsedDelta(delta)
        - If condition: setCondition(val)
        - If hungerChange: setHungerChange(val)
```

---

### TradeTransaction (SELL)

Player sells to trader.

**Client Sends:**
```lua
sendClientCommand("DynamicTrading_V2", "TradeTransaction", {
    traderUUID = uuid,
    itemID = inventoryItemID,  -- Unique item instance ID
    item = "Base.Apple",
    transactionType = "sell"
})
```

**Server Process:**

1. **Item Location:**
   - Recursive search in player inventory (including containers)
   - Validate ownership

2. **Validation:**
   - Calculate price via `Economy.V2.GetSellPrice(itemObj)` (actual condition)
   - Faction wealth >= sell price

3. **Execution (Atomic):**
   ```lua
   UnequipIfEquipped(player, itemObj)
   RemoveItemFromInventory(player, itemObj)
   AddMoney(player, sellPrice)  -- Bundles + loose change
   DecreaseFactionWealth(factionID, sellPrice)
   ```

4. **Deflation Update (30% Chance):**
   ```lua
   For each item tag:
       if Random(100) < 30:
           globalHeat[tag] -= sensitivity
   ```
   **Purpose:** Reduces inflation as items are sold back

5. **Sync Response:**
   ```lua
   TradeResult = {
       success = true,
       itemName = displayName,
       price = sellPrice,
       basePrice = itemBasePrice,
       isBuy = false
   }
   SyncStock = { updated faction wealth }
   ```

**Money Bundle Logic:**
```lua
totalAmount = sellPrice
bundles = floor(totalAmount / 500)  -- $500 per MoneyBundle
loose = totalAmount % 500           -- Remaining in Money item

Add bundles × MoneyBundle
Add 1 × Money (with remainder)
```

## Debug/Admin Commands

**Handler:** @NetworkServer/DebugHandlers.lua

**Security:** Requires `isAdmin()` OR `isDebugEnabled()`  
All actions logged with player name and reason.

### DebugCommand: SimulateDay

Forces daily faction simulation cycle.

**Client Sends:**
```lua
sendClientCommand("DynamicTrading", "DebugCommand", {
    action = "SimulateDay",
    reason = "Testing production"
})
```

**Server Process:**
- Calls `Simulation.UpdateDaily()`
- Calls `DynamicTrading_Engine.DailyTick()`
- Logs forced simulation
- Responds with success confirmation

---

**Args:**

```lua
    action = "createTestFaction",
    town = "Rosewood",  -- Optional
```

**Server Process:**
- Generates unique faction ID
- Creates faction with random name
- Assigns town location
- Generates roster (default pop)

---

### DebugCommand: WipeFactions

Clears all factions and reinitializes defaults.

**WARNING:** Destructive operation!

**Server Process:**
1. Clear DynamicTrading_Factions ModData
2. Clear all roster souls
3. Call `Lifecycle.Init()` (recreates Independent + towns)
4. Transmit full reinit
5. Respond with confirmation

---

### DebugCommand: ForceRestock

Resets trader restock timer to trigger immediate restock.

**Args:**
```lua
{

```

**Server Process:**
- Set `lastRestockTime = currentTime - restockInterval - 1`
- Next stock check will trigger regen
- Respond with confirmation

### DebugCommand: ModifySoul

Adds/removes souls from faction roster.


- `add`: Calls `AddSoul()` count times

## Error Handling

All handlers use try-catch pattern:

```lua
local success, err = pcall(function()
    -- Handler logic
end)

if not success then
    SendResponse(player, MODULE, "Error", {
        success = false,
        reason = tostring(err)
    })
end
```

**Common Error Cases:**
- Item not in stock → "Insufficient stock"
- Player broke → "Insufficient funds"
- Faction broke → "Trader cannot afford"
- Invalid item → "Item not found in registry"
- Admin required → "Permission denied"

## Security Considerations

1. **Server Authority:** All critical data modified server-side only
2. **Validation:** Prices recalculated server-side (client cannot fake)
3. **Atomic Transactions:** Money/stock/wealth updated together or not at all
4. **Admin Gating:** Debug commands require privileges
5. **Audit Logs:** All debug actions logged with player name
6. **Item Ownership:** Sell validates item exists in player inventory
7. **Anti-Exploit:** Heat system prevents price manipulation via rapid trades

## Performance Optimizations

- **Roster filtering:** Only syncs "Trading" status (reduces 50-70% data)
- **Lazy sync:** Only sends changed data
- **Batch operations:** ModifySoul can add/remove multiple at once
- **Cached calculations:** Heat updates use pre-calculated sensitivity
- **Selective transmit:** ModData.transmit(key) instead of global

## Best Practices

1. **Always validate client data** - Never trust client-provided prices
2. **Use ServerHelpers.Send Response** - Consistent response format
3. **Log admin actions** - Audit trail for debugging
4. **Handle nil gracefully** - Check existence before accessing
5. **Transmit after changes** - ModData.transmit() after modifications
6. **Provide detailed errors** - Help client UI display issues
7. **Test edge cases** - Zero stock, zero wealth, missing items
