Title: Configuration Validation Rules
Tags: [chunk, internal, config, validation, registry]

VALIDATION FRAMEWORK:

All items in Config.MasterList must pass:
1. Identifier check: item field must exist and be non-empty string
2. Price validation: basePrice > 0, must be number type
3. Tag validation: tags must be array, each tag must exist in Tags registry
4. Stock range: {min, max} where min <= max, both positive integers
5. Category inference: Extract parent category from first tag (Food.Cooking → Food)

VALIDATION FLOW:
function ValidateItem(item)
  if not item.item then return false, "Missing item ID" end
  if not tonumber(item.basePrice) then return false, "Invalid price" end
  for _, tag in ipairs(item.tags or {}) do
    if not DynamicTrading.Tags.GetTag(tag) then
      return false, "Tag " .. tag .. " not registered"
    end
  end
  return true
end

ARCHETYPE ALLOCATION VALIDATION:
- Each archetype must have: id, name, tags{}, items{}
- Tags must match registered tag hierarchy (Parent.Child)
- Item allocations use AllocationRules table with weights
- Verify all items in allocation are registered in MasterList
- Calculate total weight and validate against probability ranges

SANDBOX OPTION VALIDATION:
Config reads from SandboxOptions:
- MinPrice, MaxPrice must be positive numbers
- PriceMultiplier must be >= 0.1
- StockMultiplier must be >= 0.1
- EventFrequency must be positive integer
- TextLength must be "Short", "Long", or "VeryLong"

ERROR HANDLING:
- Missing registry entry → log warning, skip item
- Invalid price → use default basePrice (50)
- Invalid tags → filter out non-registered tags
- Invalid stock range → use fallback {min=1, max=3}

UNIT TESTS:
- RegistryKeys: Verify all items have unique IDs
- TagInheritance: Verify parent tags exist for all child tags
- PriceRange: Verify prices fit within sandbox min/max bounds
- AllocationCoverage: Verify all archetype items are registered
