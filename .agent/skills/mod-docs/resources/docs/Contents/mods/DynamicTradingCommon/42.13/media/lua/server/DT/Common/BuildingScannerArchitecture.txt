Title: Building Scanner Architecture & Location Database
Tags: [chunk, internal, server, buildings, locations, cache]

SCANNING MECHANISM:

First load: OnServerStarted() trigger
- Scan entire map for buildings (performance intensive)
- Scan occurs in background over several game minutes
- Cache stored in ModData:DT_Buildings for persistence

Subsequent loads: Use cached data
- Load ModData:DT_Buildings from save file
- Skip full scan unless cache invalid

Manual rescan: /dtm rescan command
- Admin-only command
- Triggers full scan and overwrites cache
- Takes ~2-5 minutes depending on map size

BUILDING IDENTIFICATION:

Scanning criteria:
- IsoObject with buildingName property
- Has room definitions (multi-tile structures)
- Common buildings: houses, stores, offices, farms, hospitals

Stored properties:
{
  x = <grid_x>,
  y = <grid_y>,
  z = <floor_level>,
  buildingName = "House" | "GeneralStore" | "Farm" | ...,
  rooms = { <room count> },
  area = <approximate tile count>
}

LOCATION DATABASE STRUCTURE:

ModData:DT_Buildings = {
  [countryName] = {
    [buildingType] = {
      { x=500, y=600, z=0, area=120 },
      { x=501, y=600, z=0, area=120 },
      ...
    }
  }
}

County mapping:
- West Point: West Point Hospital, General Store, Residences
- Muldraugh: Muldraugh Town Hall, Gas Station
- Rosewood: Rosewood Farm, School, Residences
- Riverside: Prison, Factory, Houses

CATEGORY TYPES:

Residential:
- Small House: 5-15 rooms, 200-400 tiles
- Large House: 15-30 rooms, 600-1200 tiles
- Apartment: 20-40 units, 1500-3000 tiles

Commercial:
- GeneralStore: 3-5 rooms, 300-500 tiles
- GasStation: 2-3 rooms, 150-300 tiles
- Restaurant: 3-6 rooms, 400-700 tiles

Industrial:
- Farm: 2-8 structures, 2000-5000 tiles
- Factory: 5-15 rooms, 5000-10000 tiles
- Warehouse: 1-3 large rooms, 3000-8000 tiles

Institutional:
- Hospital: 10-20 rooms, 2000-4000 tiles
- Prison: 15-30 rooms, 3000-6000 tiles
- School: 8-15 rooms, 1500-3500 tiles

USAGE IN QUESTS:

Event system calls building scanner:
```
function SelectRandomLocation(buildingType)
  local buildings = DT_BuildingScanner.GetBuildingsByType(buildingType)
  if #buildings == 0 then return nil end
  return buildings[math.random(1, #buildings)]
end
```

Quest creation example:
- Quest: "Find supplies in a house"
- Call: SelectRandomLocation("House")
- Result: Random house location {x, y, z}
- UI displays: "Go to house at (x, y)"

FACTION BASE SELECTION:

Factions claim buildings as bases:
```
function AssignFactionBase(faction)
  local possibleBases = GetBuildingsByType("LargeHouse", "GeneralStore")
  local selectedBase = possibleBases[math.random(1, #possibleBases)]
  faction.baseLocation = selectedBase
  return selectedBase
end
```

Different faction types prefer different buildings:
- Merchants: GeneralStore, TradePost
- Military: GameZone, Police, Prison
- Survivors: House, Farm, SafeZone
- Religious: ChurchZone

PERFORMANCE OPTIMIZATION:

Full scan statistics:
- Time: 2-5 minutes (background processing)
- Buildings found: 200-500 per county
- Cache size: ~50KB per county (~200KB total)

Query optimization:
```
-- Slow: Scan all buildings (deprecated)
for county, types in pairs(DT_Buildings) do
  for type, locations in pairs(types) do
    -- iterate through 1000s
  end
end

-- Fast: Index lookup by type
local stores = DT_Buildings[currentCounty]["GeneralStore"]
-- Direct access, O(1) lookup
```

Cache invalidation:
- Triggered by: /dtm rescan command
- Occurs when: Map mods added/removed (rare)
- Result: Full re-scan, overwrite ModData:DT_Buildings

NETWORKING (MP):

Single-player:
- Cache stored in local ModData
- Re-scan affects only local database

Multiplayer:
- Server maintains canonical building cache
- Clients receive building locations on demand
- Prevents scanning on each client (expensive)
- Server sends: buildingList = {location1, location2, ...}
