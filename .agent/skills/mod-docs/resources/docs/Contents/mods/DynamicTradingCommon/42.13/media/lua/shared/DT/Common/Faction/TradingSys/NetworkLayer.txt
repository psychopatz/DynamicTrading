Title: Faction Trading Network Layer
Tags: [chunk, internal]

LOCATION: Contents/mods/DynamicTradingCommon/42.13/media/lua/shared/DT/Common/Faction/TradingSys/
PURPOSE: Describe request/response command flow for multiplayer faction-trade interactions.

NETWORK PRINCIPLES:
- Server is authoritative for faction wealth, stock, and roster state.
- Client requests are validated before any mutation.
- Responses are explicit command payloads (`Sync*`/`TradeResult`) consumed by UI/state layers.

COMMON FLOWS:
1. `RequestRoster` -> server filters active trading souls -> `SyncRoster`.
2. `RequestStock` -> server returns trader inventory/restock/faction wealth -> `SyncStock`.
3. `TradeTransaction` -> validate item, stock, and funds -> atomic stock+wealth update -> `TradeResult` + `SyncStock`.
4. Admin actions (force generation/restock) -> mutation + full resync.

VALIDATION AND SAFETY:
- Reject unknown trader IDs and invalid item identifiers.
- Recalculate price server-side (never trust client total).
- Preserve item condition/fluid metadata when transferring inventory instances.
- Emit logs for rejected commands and suspicious input patterns.
