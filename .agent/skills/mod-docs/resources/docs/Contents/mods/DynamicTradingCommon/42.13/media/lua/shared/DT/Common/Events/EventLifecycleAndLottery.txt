Title: Event Lifecycle and Lottery Processing
Tags: [chunk, internal]

LOCATION: Contents/mods/DynamicTradingCommon/42.13/media/lua/shared/DT/Common/Events/DT_EventManager.lua
PURPOSE: Document event activation, cooldown, and hourly processing behavior.

HOURLY TICK FLOW:
1. Expire active flash events when current time exceeds expiration.
2. Apply cooldown to expired flash events (prevents immediate retrigger).
3. Re-evaluate seasonal/meta conditions and toggle them on/off.
4. Run flash-event lottery if active-count/frequency/chance checks pass.
5. Rebuild active event cache for pricing and stock systems.

FLASH LOTTERY CHECKS:
- Active flash events must be below max concurrent limit.
- Days since last trigger must be >= configured frequency.
- Random roll must pass configured chance threshold.
- Candidate pool prefers non-cooldown events, then fallback pool if needed.

MULTIPLIER APPLICATION:
- `priceMult` and `stockMult` are applied per matching tag.
- Multiple active events compound multiplicatively.
- Tag-specific effects can use broad tags (`Food`) or wildcard-like groups (`Food.*`).

FACTION IMPACT SUPPORT:
- Events can define target casualties, attrition, and consumption modifiers.
- Casualties are typically distributed across remaining event lifetime.
- Attrition uses resource checks (for example meds/food/fuel) before applying deaths.

ADMIN TESTING:
- `/dtm events list|active|info`
- `/dtm events trigger <id> <hours>`
- `/dtm events halt <id>`
- `/dtm debug` for active multipliers/state.
