Title: 00_DT_Core - Main Initialization and Registration APIs
Tags: [core, initialization, api, registration, items, archetypes, tags]

Main entry point for DynamicTradingCommon. Runs first due to "00_" prefix. Establishes global DynamicTrading table, registration APIs, custom events, and static configuration.

## Purpose

Ensures core infrastructure is available before any other mod files load. Provides registration functions for items, archetypes, tags, and events that other mods and systems use.

## Global Tables Initialized

```lua
DynamicTrading                          -- Root namespace
DynamicTrading.Config                   -- Configuration data
DynamicTrading.Config.MasterList        -- All registered items { [itemFullType] = itemData }
DynamicTrading.Config.Tags              -- Tag registry { [tagName] = tagData }
DynamicTrading.Archetypes               -- Archetype definitions { [archetypeID] = archetypeData }
```

## Core Modules Loaded

Immediately requires critical quest modules:
- `DT/Common/Quests/DT_QuestManager` - Quest item creation/validation
- `DT/Common/Items/DT_QuestItems` - Quest item definitions

## Custom Events Registered

Adds 6 custom LuaEventManager signals for mod lifecycle hooks:

### Economy & Simulation Events
- **OnDynamicTradingDailySimulation** - Daily faction/economy update tick
  - Used by: Faction simulation, event processing, restock cycles
  - Frequency: Once per in-game day

- **OnDynamicTradingHourlyTick** - Hourly simulation trigger
  - Used by: Event expiration, short-term cooldowns
  - Frequency: Every in-game hour

### UI & Network Sync Events
- **OnDynamicTradingTraderUpdated** - Trader data changed (inventory, visuals)
  - Used by: UI refresh, client cache invalidation
  - Triggered when: Stock changes, trader spawns/despawns

- **OnDynamicTradingFactionUpdated** - Faction state changed
  - Used by: Reputation UI, faction list updates
  - Triggered when: Member count changes, wealth changes, casualties

- **OnDynamicTradingStockUpdated** - Player inventory synced
  - Used by: Trade validation, stock refresh
  - Triggered when: Trade completes, restock occurs

- **OnDynamicTradingTradeCompleted** - Transaction finished
  - Used by: Analytics, quest tracking, achievement systems
  - Triggered when: Buy/sell operation succeeds

## Registration API Functions

### DynamicTrading.RegisterTag(tag, data)

Registers a tag with pricing and spawn weight modifiers.

**Parameters:**
- `tag` (string) - Tag name (e.g., "Food.Canned", "Weapon.Firearm")
- `data` (table) - Tag configuration:
  - `priceMult` (number, default 1.0) - Price multiplier (0.1-10.0)
  - `weight` (number, default 50) - Spawn weight for random selection (1-100)

**Usage:**
```lua
DynamicTrading.RegisterTag("Food.Canned", {
    priceMult = 1.2,  -- 20% more expensive than baseline
    weight = 80       -- High spawn chance
})

DynamicTrading.RegisterTag("Weapon.Rare", {
    priceMult = 5.0,  -- 5x expensive
    weight = 5        -- Low spawn chance
})
```

**Notes:**
- Tags without `priceMult` default to 1.0 (no price change)
- Tags without `weight` default to 50 (medium spawn rate)
- Tag hierarchy uses dot notation (Category.SubCategory.Detail)

### DynamicTrading.RegisterArchetype(id, data)

Registers a trader archetype with stock allocations, expertise, wants, and forbidden items.

**Parameters:**
- `id` (string) - Unique archetype ID (e.g., "Farmer", "Gunrunner", "Doctor")
- `data` (table) - Archetype configuration:
  - `name` (string, default=id) - Display name
  - `allocations` (array) - Stock generation rules: `{ { tags={...}, count=N }, ... }`
  - `expertTags` (array) - Tags this archetype sells cheaper/buys higher (expertise bonus)
  - `wants` (table) - Items this archetype pays premium for: `{ [tag] = multiplier }`
  - `forbid` (array) - Tags this archetype NEVER stocks

**Usage:**
```lua
DynamicTrading.RegisterArchetype("Farmer", {
    name = "Farmer",
    allocations = {
        { tags = {"Food.Fresh"}, count = 10 },
        { tags = {"Food.Vegetable"}, count = 8 },
        { tags = {"Tool.Farming"}, count = 5 }
    },
    expertTags = { "Food.Fresh", "Food.Vegetable" },  -- 20% discount on these
    wants = {
        ["Resource.Fuel"] = 1.5,    -- Pays 50% more for fuel
        ["Tool.Mechanical"] = 1.3   -- Pays 30% more for tools
    },
    forbid = { "Weapon.Firearm", "Weapon.Ammo" }  -- Never stocks weapons
})
```

**Allocation Structure:**
- `tags` = Array of tag patterns (ANY match = item eligible)
- `count` = Number of unique items to generate from matching pool

**Expert Tags:**
- Players SELL to expert 20-30% higher than baseline
- Players BUY from expert 10-20% cheaper than baseline

**Wants System:**
- Multiplier > 1.0 = Archetype pays premium (e.g., 1.5 = 50% more)
- Applied when player SELLS matching items to this trader

**Forbid System:**
- Prevents items with matching tags from appearing in stock
- Overrides allocations (forbid takes precedence)

### DynamicTrading.AddItem(uniqueID, data)

Registers an item in the master list for trading system.

**Parameters:**
- `uniqueID` (string) - Full item type (e.g., "Base.Apple", "Brita.M16")
- `data` (table) - Item configuration:
  - `basePrice` (number, default 10) - Base value in currency
  - `tags` (array, default {"Misc"}) - Category tags for matching allocations
  - `stockRange` (table, default {min=1, max=5}) - Min/max stock quantities
  - `customData` (table, optional) - Additional properties (uses, condition, etc.)

**Usage:**
```lua
-- Basic item registration
DynamicTrading.AddItem("Base.Apple", {
    basePrice = 5,
    tags = { "Food.Fresh", "Food.Fruit" },
    stockRange = { min = 3, max = 15 }
})

-- Advanced with custom data
DynamicTrading.AddItem("Base.Bandage", {
    basePrice = 20,
    tags = { "Medical.Supply", "Medical.Wound" },
    stockRange = { min = 5, max = 20 },
    customData = {
        uses = 5,      -- Drainable item
        perishable = false
    }
})

-- Rare item with low stock
DynamicTrading.AddItem("Base.GoldBar", {
    basePrice = 5000,
    tags = { "Currency", "Rarity.Legendary" },
    stockRange = { min = 0, max = 2 }
})
```

**Validation:**
- If `tags` array is empty or invalid, automatically adds "Misc"
- Prints debug message if `isDebugEnabled()` is true
- Stored directly in `DynamicTrading.Config.MasterList[uniqueID]`

**Tag Matching:**
- Items match allocations if ANY tag in item.tags appears in allocation.tags
- Multiple tag matches increase spawn weight

**Stock Range:**
- `min` = Minimum quantity trader will have after restock
- `max` = Maximum quantity trader will have after restock
- Actual quantity randomized within range, modified by difficulty multipliers

### DynamicTrading.GetMasterListCount()

Returns total number of registered items.

**Returns:** (number) Count of items in MasterList

**Usage:**
```lua
local itemCount = DynamicTrading.GetMasterListCount()
print("Total items registered: " .. itemCount)
```

**Purpose:**
- Debugging and validation
- Progress tracking during batch registration
- Performance monitoring (large counts may need optimization)

## Execution Order

1. **Global table initialization** - Creates namespaces
2. **Core module loading** - Requires quest modules
3. **Event registration** - Adds custom signals to LuaEventManager
4. **Static config** - Defines radio tiers
5. **API definition** - Exposes registration functions
6. **Counter utility** - Provides GetMasterListCount()
7. **Debug print** - Logs initialization with current item count

## Usage Patterns

### Item Registration Workflow

```lua
-- 1. Register relevant tags first
DynamicTrading.RegisterTag("Custom.Category", { priceMult = 1.5, weight = 40 })

-- 2. Register archetype that uses the tag
DynamicTrading.RegisterArchetype("CustomTrader", {
    allocations = { { tags = {"Custom.Category"}, count = 10 } },
    expertTags = { "Custom.Category" }
})

-- 3. Register items with the tag
DynamicTrading.AddItem("MyMod.CustomItem", {
    basePrice = 100,
    tags = { "Custom.Category" },
    stockRange = { min = 2, max = 8 }
})
```

### Batch Registration

```lua
local itemList = {
    { id = "Base.Apple", price = 5, tags = {"Food.Fruit"} },
    { id = "Base.Bread", price = 10, tags = {"Food.Baked"} },
    { id = "Base.Water", price = 3, tags = {"Drink.Water"} }
}

for _, item in ipairs(itemList) do
    DynamicTrading.AddItem(item.id, {
        basePrice = item.price,
        tags = item.tags,
        stockRange = { min = 1, max = 10 }
    })
end

print("Registered " .. #itemList .. " items. Total: " .. DynamicTrading.GetMasterListCount())
```

## Performance Considerations

- **Item registration is fast** - Direct table insertion, O(1) lookup
- **No validation overhead** - Minimal checks for flexibility
- **Debug printing conditional** - Only logs when debug enabled
- **Lazy loading** - Detailed item data loaded on first access

## Best Practices

1. **Register tags before archetypes** - Archetypes reference tags in allocations
2. **Register archetypes before items** - Helps verify tag coverage
3. **Use consistent tag hierarchy** - Follow convention: Category.SubCategory.Detail
4. **Provide meaningful stockRange** - Base on item rarity and weight
5. **Set realistic basePrices** - Consider game economy balance
6. **Document custom tags** - If creating new taxonomy, document purpose
7. **Test with debug enabled** - Verify registration prints show expected items

## Common Pitfalls

- **Missing tags array** - Always provide at least one tag, or "Misc" is auto-added
- **Duplicate item IDs** - Last registration overwrites previous (no warning)
- **Invalid tag references** - Archetypes can reference non-existent tags (no validation)
- **Circular dependencies** - Don't require 00_DT_Core from other files (already global)
- **Event timing** - Custom events only available AFTER this file loads
