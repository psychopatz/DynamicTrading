Title: Config Archetype Loading and Dialogue Pipeline
Tags: [chunk, internal]

LOCATION: Contents/mods/DynamicTradingCommon/42.13/media/lua/shared/DT/Common/Config.lua
PURPOSE: Document how archetypes and multilingual dialogue are loaded and merged.

LOADING PIPELINE:
1. Iterate configured archetype list (40+ archetypes plus meta entries).
2. Load item allocations from `ArchetypeDefinitions/<id>/Items/DT_<id>.lua`.
3. Load base dialogue files for types: Greetings, Buying, Selling, Sell_ask, Idle, Request.
4. Load language overrides from `Dialogue/Translations/<lang>/...` when present.
5. Merge into `DynamicTrading.Dialogue.Archetypes[id][dialogueType][lang]`.

MERGE RULES:
- Base language content is loaded first.
- Translation files add or override language-specific entries.
- Missing translation files are skipped without hard failure.
- Missing item definition should be treated as a warning during validation.

REGISTRATION APIS USED:
- `DynamicTrading.RegisterArchetype(id, data)`
- `DynamicTrading.RegisterDialogue(archetypeID, dialogueType, data)`
- `DynamicTrading.RegisterBatch(list)` and `DynamicTrading.AddItem(id, data)` for item population.

LANGUAGE RESOLUTION:
- Runtime uses `DynamicTrading.GetLanguage()`.
- Fallback is `EN` if translation API is unavailable.
- Dialogue selection should always degrade to English safely.

DEBUG AND SAFETY:
- Loader uses file existence checks to avoid require spam.
- Optional debug mode can print per-file load results.
- Recommended validation pass after adding new archetype folders or translations.
